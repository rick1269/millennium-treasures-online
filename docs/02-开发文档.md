# 《千年藏珍》开发文档

版本 1.0 · 基础版。规范顺序：**机制 → 主题 → 组件 → 规则**。`01-规则漏洞与修订.md` 记录从原案到本版的全部裁决；本文件和《03-小白说明书.md》是实际玩法依据。

## 1. 机制：玩家到底在做什么

核心循环是“主持人选品 → 公开竞价 → 秘密竞价 → 二次交易 → 银行回收 → 换庄”。玩家在有限金币与隐藏手牌之间取舍：买单卡可增加基础分，集中收藏同一时代能提高整套估值，但红卡带来每回合波动和终局风险。

| 机制 | 输入 | 输出 | 玩家决策 |
|---|---|---|---|
| 双拍卖 | 每回合最多 2 张候选卡 | 藏品归属、金币流动 | 高低星配置、竞价上限 |
| 资金骰 | 中标报价与藏品星级 | 实付金额及佣金 | 承受资金不足的风险 |
| 二次交易 | 主持人的 1 张已有藏品 | 换卡或二次暗拍 | 套组交换与变现 |
| 银行出售 | 非主持玩家的最多 1 张牌 | 金币与弃牌 | 回笼现金、拆套风险 |
| 红卡 | 当回合持有的红卡 | 小额收益或损失 | 继续收藏还是转手 |
| 终局套组 | 同时代的星级种类 | 1 倍 / 1.5 倍 / 2 倍估值及惩罚 | 集中或分散收藏 |

设计目标：规则可以由游戏自动裁决，玩家能解释每笔钱和每一分从何而来。基础版不加入赝品、鉴定、时代特性。

## 2. 主题：为什么是文物拍卖

九大时代从春秋战国到民国，各时代形成一个收藏系列。红卡代表传奇藏品：珍贵却需同系列配套才能安全持有。主持人代表当轮拍卖行，控制候选品、收取正式拍卖佣金；其他人是藏家。风格为深色展柜、铜金铭牌与朱红传奇卡。

卡名沿用原设计案，属游戏化表达。真实历史归属需在印刷或公众教育使用前逐件核证；不得以本游戏卡面作为文物史实证明。

## 3. 组件：桌面版与网页版同构

| 组件 | 数量 / 形式 | 说明 |
|---|---|---|
| 藏品卡 | 全库 81 张；每局抽 N 个时代共 `9N` 张，再移走 1 张红卡 | 每时代 1 星×3、2 星×3、3 星×2、红卡×1；同名副本用编号区分 |
| 金币 | 建议至少 900 枚等值筹码或记分纸 | 6 人初始共 900 金；银行可用账本无限记账 |
| 六面骰 | 2 枚 | 低星掷 1 颗，高星掷 2 颗；红卡掷 1 颗 |
| 玩家标记 | 6 个 | 入席顺序用于轮换与平手裁决 |
| 倍率轨 | 低星、高星各 1 条，70%–130% | 初始都是 100% |
| 隐藏红卡封套 | 1 个 | 开局随机移走 1 张，终局揭示 |
| 卡面文件 | `cards/assets.csv` | 81 张网页卡面、统一卡背、总览和独立插画均按卡牌 ID 索引；旧 SVG 保存在 `cards/print/` |
| 数据目录 | `web/data/rooms.json` | 网页房间存档，服务器重启后恢复；房间令牌仅存在本机文件 |

藏品名录及副本数量以 `cards/catalog.csv` 为准；Web 的规则数据源是 `web/catalog.js`，制卡脚本从同一数据源生成印刷文件。图片的**唯一选择入口**是 `cards/assets.csv`，与规则数据分离：更换卡面不改变牌的效果或数量。路径相对 `cards/`；`@version` 为整套图片版本号；首次校验自动将映射和源文件 SHA-256 存入 `cards/releases/`。已归档版本不能改路径或源图内容；回退可运行 `npm run assets:use -- v1.0.0` 或 `v1.1.0`。详见 `cards/README.md`。

## 4. 规则：可直接实现的完整裁决

### 4.1 开局

3–6 个席位各领 150 金，按入席顺序就座。房主可在开局前配置 0 至剩余席位数的机器人；单人试玩至少添加 2 位机器人。机器人和真人遵守完全相同的金币、手牌、竞拍及轮换规则。随机抽与总席位数相同的时代；把这些时代的牌混合，随机取出一张红卡面朝下封存。其余牌洗匀。确定第一位主持人。共进行 `总席位数×3` 回合，每位藏家恰好主持三次。

### 4.2 每回合六阶段

1. **开局事件。** 所有当前持有的红卡逐张执行红卡骰；再分别掷低星 1D6、高星 2D6，调整两条银行收购倍率。先做事件，后交易。首回合也调整倍率。
2. **选品。** 主持人抽最多 5 张，选两张不同星级的实体卡：一张明拍、一张暗拍。候选全同星时可例外选任意两张。未选的卡入弃牌区。牌堆空则将弃牌区洗回；总共不足两张时跳过两场正式拍卖。
3. **明拍。** 仅非主持且未禁拍者参加，按入席顺序轮流喊价或永久退出。起拍价 `max(5,基础估值÷2)`，之后每次至少加 2。最后最高价者暂中标；无人报价则流拍。
4. **暗拍。** 同样的合格玩家各提交一次秘密整数报价，0 为放弃，正报价至少起拍价。全部提交后揭示，价高者暂中标，同价按入席顺序。
5. **二次交易。** 主持人从“跳过 / 用自己一张卡提出一次 1 对 1 换卡 / 用自己一张卡进行二次暗拍”中选一项。换卡对方可拒，拒绝后本阶段结束。二次拍卖卖家不出价，所得成交价归卖家，佣金归银行。
6. **银行出售。** 每位非主持玩家各自决定是否出售最多一张卡。银行按该卡星级适用倍率支付；选了卖则立即成交。所有人操作后换下一位主持人。

### 4.3 拍卖结算与失约

暂中标者掷资金骰：1–2 星掷 1D6，对应 `+1,+2,+3,−1,−2,−3`；3–4 星掷 2D6，点数 2–6 对应 `+2…+6`，7 为 0，8/9/10/11/12 对应 `−2/−3/−4/−5/−6`。实际货款 `max(0,报价+修正)`，佣金 `max(1,ceil(实际货款×0.1))`，总支出为两者之和。

若金币不足，当前竞买人不付款也不拿卡，下一个主持回合全禁拍；按报价由高到低依次尝试下一人（同价按入席顺序）。所有人失约或无人出价则流拍：正式拍卖的卡进入弃牌区，二次拍卖的卡退还原卖家。正式拍卖的货款进入银行、佣金归主持人。二次拍卖的货款归卖家、佣金进入银行。明拍、暗拍、二次暗拍统一使用该结算。

### 4.4 倍率与红卡

低星骰 1–3：倍率 −10 个百分点；4–6：+10。高星骰和 2–6：−10；7：0；8–12：+10。两条倍率独立累积，限制在 70%–130%。银行收购价 `max(ceil(基础估值×0.5),floor(基础估值×对应倍率))`。倍率**只影响银行出售**，不影响终局分。

红卡每回合开始掷 1D6：4–6 获得同一时代持卡实体张数的金币；1–3 失去非该时代持卡实体张数的金币，金币最低 0。持有该时代至少一张 1、2、3 星卡以及红卡时，免除红卡的负面结果。红卡转手后的下一回合由新持有者执行；卖出后不执行。

### 4.5 终局分

对每个时代单独计算持卡基础估值之和。如果同时持有 1、2、3 星：无红卡乘 1.5，有红卡乘 2；否则乘 1。若有红卡却缺任一 1/2/3 星，额外扣该时代**基础估值之和×2**。总分 = 剩余金币 + 各时代加成估值 − 各时代红卡惩罚。允许负分；同分依次比金币、完整四星套数、入席顺序。

### 4.6 数字实现边界

所有由玩家提交的金额须为安全范围内的非负整数，不超过当前金币。服务端是唯一裁判；客户端只显示自己的非红卡手牌，公开其他玩家的红卡和卡数。房主负责开局及开局前的机器人数量，当前主持人负责选品和进入下一回合。机器人由服务端在轮到它时执行动作；外部请求不能冒用机器人身份。房间状态每次操作后保存。房间链接中的六位码可公开旁观，个人令牌保存在加入者浏览器中；不要分享浏览器的本地存储内容。

### 4.7 机器人策略

机器人使用可复现的规则策略：竞价上限由藏品基础价、同系列已持有星级和当前金币决定，预留资金骰与佣金空间；明拍不超过上限才加价，暗拍在起拍价附近报价。持有不完整红卡的机器人主持二次拍卖时可尝试卖出；出售阶段只在按当前分数计算有净收益时卖卡；被提出换卡时仅接受能提高自身当前总分的交换。机器人不读取其他玩家的秘密手牌，也不获得隐藏红卡信息。策略用于单人练习与小范围试玩，不宣称与真人对手同等水平。
